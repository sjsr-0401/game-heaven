# 모드 개발 안내

## 책임 분리

공통 방은 플레이어와 연결 상태, 방장, 준비 여부, 게임 세션의 생명주기만 관리합니다.
웨이브·타워·영토·승리 조건 등은 모드 세션 안에 둡니다. 공통 코드에 모드 ID로 분기하는 규칙을 추가하지 마세요.

서버의 `GameMode`가 메타데이터와 `create(players, seed)`를 제공하고, 만들어진 `ModeSession`이 다음 계약을 구현합니다.

- `command(playerId, action)`: 검증 후 명령 반영. 자원과 소유권 검사는 반드시 서버에서 수행.
- `tick(dt)`: 고정된 시간 간격으로 시뮬레이션.
- `snapshot()`: 공개 가능한 직렬화 상태만 반환.
- `finished()`: 결과 단계로 전환할지 반환.
- `playerLeft(playerId)`: 명시적 이탈·재접속 유예 만료 시 정리. 일시 단절에는 호출하지 않음.

클라이언트 `ModeFactory`는 제공된 영역에 화면을 만들고 `update(room)`, `destroy()`를 구현합니다.
명령은 제공된 `context.command`로 전송하고, 자체 네트워크 연결을 만들지 않습니다.
`destroy`에서 애니메이션과 이벤트 리스너를 정리해야 합니다.

## 새 모드 추가

1. `shared/`에 해당 모드의 상태와 명령 타입을 정의합니다. 게임 규칙에 쓰이는 수치를 한 곳에 둡니다.
2. `server/modes/<id>.ts`에 `GameMode`와 세션을 구현합니다.
3. `server/modes/registry.ts`에 등록합니다.
4. `src/modes/<id>/`에 화면을 만들고 `src/modes/registry.ts`에 등록합니다.
5. 모드 고유 동작 테스트를 작성하고 기존 방 테스트가 그대로 통과하는지 확인합니다.
6. 클라우드 녹화 시나리오를 추가하거나 변경합니다. 미리보기 영상이 게임의 실제 상태를 사용하게 하세요.

새 규칙에 필요한 공통 기능은 실제 두 번째 사용처가 생겼을 때 분리합니다.
방 메시지의 공통 의미를 바꾸면 `PROTOCOL_VERSION`을 올리고 클라이언트도 함께 배포합니다.

## 모드 제거

서버와 클라이언트 등록부에서 해당 항목을 제거하고 함께 배포합니다.
실행 중인 서버에서 등록부를 바꾸는 핫 리로드는 지원하지 않습니다. 서버 재시작은 진행 중인 방을 종료합니다.
이미 제거된 모드 ID로 방을 만들려는 요청은 서버가 거절합니다.

## 검증

`tests/rooms.test.ts`는 디펜스와 무관한 테스트용 모드를 등록해 시작·종료·대기실 복귀를 검사합니다.
밤의 용병단의 개인 전장 격리·소유권·소환 확률·자원·스킬·승패 테스트는 `tests/defense.test.ts`에 있습니다.
여러 실제 추첨 시드의 전체 런은 `tests/balance.test.ts`로 검사합니다.
실제 WebSocket 연결과 두 브라우저의 동기화, 새로고침 재접속은 `scripts/review.ts`가 검사합니다.

서버는 단일 프로세스의 메모리에 방을 보관합니다. 서버 재시작 복구, 다중 서버 분산, 저장 게임은 현재 범위에 없습니다.
서로 다른 가정이 필요한 모드(예: 전쟁의 안개)는 전용 공개 상태 필터링을 별도로 구현해야 합니다.
